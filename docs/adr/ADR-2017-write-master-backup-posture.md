# ADR-2017 — One write-master per data class; disposable derived projections; SQLite-only online backup

## Context

The estate spans several stores (Oxigraph/RocksDB triples, four SQLite DBs,
external RuVector) with no distributed-transaction layer. Consistency and
durability cannot be assumed across them. The knowledge/assert projection is
downstream of a GitHub upstream; agent memory lives in RuVector (ADR-030); the
triple store is Oxigraph-only (ADR-132). The open risk (PRD-014 / TODO C-3) was
that the SQLite DBs had no backup at all.

## Decision

Each data class linearises at its **own** commit point with a single
authoritative store. The Oxigraph `:assert` projection is regenerated by full
`CLEAR + INSERT DATA` from the GitHub upstream and is never hand-edited —
it is disposable. Secondary fan-outs are best-effort with **no** cross-store
2PC and no tombstones. The backup script targets the four SQLite DBs using the ONLINE BACKUP API
(`.backup`) and `integrity_check`. Complete coverage and an off-volume
destination are required closeout properties, but are not enforced by the
current script: missing members are skipped and the host default remains
inside `./data`. This forecloses relying on any cross-store consistent
restore and any hand-editing of the derived triple graphs.

## Consequences

- Oxigraph/RocksDB has no PITR and no backup script: recovery is re-sync from
  GitHub, which reconstructs `:assert` but not derived/provenance graphs.
- No cross-store consistent restore exists; a partial failure can leave stores
  skewed until the next full sync.
- RuVector delete-propagation is missing — deletions upstream are silently
  dropped from the vector index. This is a defect to be fixed, not the intended
  invariant (hence implementation_status: partial).
- The SQLite snapshot primitive has executable evidence; complete backup
  coverage, separate failure domains and application-level recovery remain open.

## Acceptance progress — 2026-09-05

**Implemented.** `scripts/backup-sqlite.sh`. All three reproduced defects are
closed.

1. *Required versus optional membership.* `REQUIRED_DBS` (settings, enrichment,
   kpi — authored configuration, the proposal/decision ledger and the KPI
   lineage series, none regenerable) and `OPTIONAL_DBS` (liveness — canary
   telemetry the watchdog recreates on boot). A missing **required** member now
   fails the run non-zero, removes the destination directory and writes no
   manifest: a backup set that silently omits the settings database is worse
   than no backup, because it looks restorable. A missing optional member is
   logged, skipped, and recorded in the manifest.
2. *Destination outside the source.* The default `BACKUP_ROOT` moves from
   `./data/backups` to `./backups/sqlite`, and a destination that resolves
   inside the host source directory is refused outright — writing backups into
   `./data` puts them in the same failure domain as the databases they protect.
   `ALLOW_BACKUP_INSIDE_DATA=1` is an explicit, loudly warned override.
3. *Application-level restore check.* `PRAGMA integrity_check` proves the pages
   are self-consistent, not that the snapshot carries the application's schema.
   With `VERIFY_RESTORE=1` (default) each snapshot is copied to a scratch path —
   a real restore — and every table the owning adapter declares is queried. A
   page-clean snapshot of a schema-less file fails. Opting out is recorded in
   the manifest.

**Tests.** `cargo test -p visionclaw-integration-tests --test backup_posture` —
10 passed, 0 failed. The tests drive the real script in `MODE=host` against
throwaway SQLite fixtures and touch nothing outside a temporary directory:
complete source; missing required fails and publishes nothing; missing optional
succeeds and is recorded; reclassifying a member moves it across the boundary;
inside-source destination refused; override accepted with a warning; the shipped
default asserted outside `./data`; a page-clean schema-less database failing the
restore check by name; live row counts reported from the restored copy; and the
opt-out recorded.

**Receipts.** `docs/estate-closeout/2026-09-05/adr-2017-backup-posture.txt`.

**Remains open.** No production restore ran, and backup failure-domain
separation is enforced for the host mode only (docker mode writes to a
host-visible path by construction, but that is not asserted). Full-sync
generation staging, and ownership of runtime assertions and agent-graph resets,
are untouched.
