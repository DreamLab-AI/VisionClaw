# ADR-2204 — Relations have one declarative schema and one weighting stage

Amends ADR-2140 (one stored definition, no scale factors) by extending it from
force *parameters* to the *relations* the forces act on. Related: ADR-2183 D4
(hierarchy collapse removes from the render set), ADR-2192 (stored operator
switches), ADR-2191 (device buffers declared once).

## Context

- **No owner for relation meaning.** A relation is typed, weighted, scaled or coloured in eight tables that disagree: the sync's predicate→label map and `weight = strength × 2` (`github_sync_service.rs:2135-2170`, `:2758-2790`), the 49-row semantic type registry with its own strengths and rest lengths (`semantic_type_registry.rs:148-606`), the `SemanticEdgeType` enum (`edge.rs:27`), literal weights for wikilinks, `elevated_from`, domain spokes and inferred edges, an uncapped co-citation sum (0.5 per shared target, two passes), the client colour table (`useGraphNodeColors.ts:27`) and the XR tables. The ontology constraint mapper adds eight more constants (`ontology_constraint_mapper.rs:65-92`). Inventory at `0df0fce98`.
- **One relation, three forces.** Each typed edge enters the LinLog spring with `strength × 2`, the attribute spring with a rest length that goes negative above w = 1.18 (`semantic_forces.cu:357-400`), and the dynamic-relationship force with the raw strength and its own rest length (`:492-562`). Repeated relations on a pair add as separate springs (`force_compute_actor.rs:952-983`). **Repulsion has no owner either:** `upload_degree_weights` fills `degree_weight` and sets `degree_weights_available` (`memory.rs:813-830`), which selects the FA2 branch, but the kernel is passed `node_degrees` (`execution.rs:688-690`), a zero-initialised buffer (`buffers.rs:182`) that only the community-detection paths write (`community.rs:139`, `:354`; `leiden.rs:226`). Live FA2 repulsion is therefore uniform until community detection runs, after which the same flag reads weighted degrees and repulsion silently becomes degree-weighted. (Replica: uniform repulsion kNN lift 60–64, domain lift 6.16–6.24; degree-weighted 68–70, 6.00–6.13 — the analytics run changes the physics measurably.)
- **Reload loses the edge.** Missing weights become 1.0 and edge metadata is dropped (`oxigraph_graph_repository.rs:1495`, `:1512`).
- **Measured, preliminary** (GPU replica of the force pass, 9,679 nodes, single seed, labels the forces never read): weighting changes *fidelity* (graph neighbours close: kNN lift 68–89) far more than *held-out structure* (domain lift 5.7–6.1 for every weighting). Edge cuts never beat the full graph on held-out labels. These numbers are not acceptance thresholds.
- **Cross-family design audit** (codex `gpt-6-astra`, 2026-11-19, `urn:agentbox:activity:11ed6422…`): centralisation sound; normalisation, evidence identity, repulsion matching, constraint scope and domain-spoke circularity under-specified. This revision answers each.

## Decision

1. **One relation schema.** `crates/visionclaw-domain/data/relations.yaml` (compiled in with `include_str!`; not under `/app/data`, which a named volume shadows in dev) is the only definition of a relation. Each entry names: the label; the OWL predicate IRIs and frontmatter keys that produce it, and its inverse predicate if any; its `kind` (`hierarchy` | `typed` | `link` | `derived`); its **affinity** `a ∈ (0,1)` — a versioned policy value with its rationale, not a calibrated probability; whether it takes part in physics; whether it is drawn by default; its colour. The sync, store, GPU upload, REST/initial-load payload, desktop client and XR client read this schema or a JSON projection generated from it, pinned by producer/consumer fixture tests (the ADR-2140 D5 pattern). An unknown predicate is quarantined (kept in the store with its raw IRI, counted, excluded from physics and drawing), never auto-registered with invented values.
2. **Evidence identity.** A relation instance is `(source, target, predicate, provenance)`. Before weighting, instances are reduced to evidence items: an inverse-predicate assertion is the same item as its forward form; an inferred instance that duplicates an asserted one adds nothing; hierarchy contributes **direct** parent edges only, never the reasoner's transitive closure; co-citation is one item per `(pair, shared target)`. Self-loops are dropped. The store and wire keep every instance with direction and provenance; only the weighting stage collapses them. **This depends on D3's input carrying provenance, which today is lost on reload and mislabelled at source (the inferred-edge materialiser emits `hierarchical`): the round trip (E3) and correct provenance labelling are built first, and evidence identity is enforced only once they hold.**
3. **One weighting stage, at graph build.** A single module computes, once per graph build, one undirected physics edge per pair with evidence:
   - affinity `q_uv = 1 − Π(1 − a_i)` over the pair's evidence items (a saturating combination, not an independence claim);
   - co-citation items take `a_cocite / ln(e + deg_t)` for shared target `t` (resource-allocation style, so a popular target contributes little), and a target with more referrers than the existing fan-out threshold (today the `FANOUT_NODE_THRESHOLD` env var at two sites, `github_sync_service.rs:570`, `:839`; moved into the schema as its single definition) creates none;
   - optional hub damping `(deg_u · deg_v)^(−α/2)` with `deg` = distinct physics neighbours computed before weighting; `α` is a stored setting, **default 0**, enabled only on measured evidence;
   - final weight `w_e = clamp(c · q_e, wMin, wMax)` with `c` solved so `Σ w_e = |E|` (mean exactly 1), `wMin ≤ 1 ≤ wMax`, normalised per connected component so adding a component never reweights another; an empty graph has no edges and no `c`.
   No other code multiplies, scales or replaces an edge weight.
4. **One attraction term; matched repulsion.** The GPU applies one spring per physics edge, `attraction ∝ w^δ` with `δ` the stored `edgeWeightInfluence` (ForceAtlas2's edge-weight influence; the kernel's existing LinLog `log(1+d)` form). Degree-weighted repulsion uses node strength `s_i = 1 + Σ_j w_ij^δ`, produced by the weighting stage and uploaded atomically with the topology and weights, so attraction and repulsion use the same weights at every `δ`. The attribute-spring and dynamic-relationship kernels no longer read relations. There is no per-relation rest length: LinLog attraction has none, and no measurement requires one; a future need is a new decision.
5. **Ontology constraint constants move into the schema.** Disjointness separation, sibling alignment and hierarchy distance stay in the constraint subsystem, but their constants move from `ontology_constraint_mapper.rs` into a `constraints:` block of the same schema, with the existing stored global strength. Until `5407bd48c` every constraint was addressed by a 31-bit persistent hash and dropped by the index, so no earlier layout included them. First live measurement after the fix (2026-11-19, 193,484 index entries, one node carrying 4,925 constraints): kNN lift 44 → 31, held-out domain lift 7.1 → 7.0, quality correlation 0.37 → 0.34 — the current constants compress the layout and add no held-out structure. Before the constants move, a strength sweep and the exclusion of top-level classes (the constraint analogue of hub damping) are measured; acceptance reports constraints on and off.
6. **Node metadata never enters an edge weight.** `quality_score`, `maturity`, file size and link counts are node attributes for visual channels (size, opacity, label priority) and filters only.
7. **Drawing is separate from physics.** Whether a relation is drawn is the schema default plus a per-viewer setting. Hiding a relation changes no physics buffer.
8. **The hierarchy comes from relations.** Client parent/child (ADR-2183 D4 collapse) comes from `kind: hierarchy` relations on the wire, supporting multiple parents and cycles, not from splitting integer node ids on `/`.
9. **Domain membership is not evaluation-neutral.** Materialised domain-root spokes are `kind: derived`. Layout acceptance metrics are computed with them removed before degree, weighting and layout; any layout with them on is reported as domain-informed.
10. **Additive wire contract.** Edges on REST/initial load gain `relations: [{label, direction, provenance}]` as an additive field beside the existing `edgeType` and `weight`; `weight` keeps its name and becomes the derived physics weight. A client that does not know `relations` ignores it and keeps drawing from `edgeType`/`weight`, so a headset build older than the server keeps working. The payload carries a minor version (recorded in `PROTOCOL-registry.md` and `GPU-wire-abi.md`); only a future major version bump is refused by clients. The binary position protocol is unchanged.

## Consequences

- Removed: the sync's predicate table, registry strengths and rest lengths as edge parameters, every literal edge weight, the `× 2`, the uncapped co-citation sum, the client and XR relation tables, the mapper's constants, and the relation paths of the two extra kernels.
- A new relation is one YAML entry; changing an affinity is a reviewed policy change with a rationale.
- The physics graph changes (≈109k evidence pairs instead of 140k typed edges); layouts change. Defaults (`δ`, `wMin`, `wMax`, `α`, affinities) are set by the measurement protocol below before activation.
- Follow-on, not decided here: server-global hierarchy folding (population scope, ADR-2192); fitting affinities against independently adjudicated assertions; `PersistentId`/`CompactId` newtypes.

## Delivery

Six slices, each merged and probed before the next relies on it: **S1** store/sync round trip of relation instances with direction and provenance (E3); **S2** (merged 3cbf9e579, value-preserving: golden edges byte-identical) `relations.yaml`, its generated projection, sync reading it, quarantine, removal of the predicate table, `× 2` and literal weights (E1); **S3** the pure weighting module (E2, including the three-encodings probe); **S4** GPU (**S4a**, repulsion owner: `repulsion_strength` is declared in `buffers.rs` and written only by `upload_repulsion` under the stored `repulsionMode` `uniform` (default) `| strength`; community detection writes its own `community_degrees`; no ABI change; **S4b** adds `δ`) — strength buffer declared in `buffers.rs` (ADR-2191), `δ` in `SimParams` (an ABI change with its `static_assert`s), relation paths of the extra kernels retired (E4); **S5** wire field, desktop and XR projection, hierarchy from relations (E5, E7); **S6** the measurement protocol, defaults, live acceptance (E6).

## Measurement protocol for defaults

The replica first implements D4 exactly (`w^δ` attraction, strength `1 + Σw^δ` repulsion) and the live repulsion branch is confirmed, so replica and CUDA measure the same model. Prediction, not reconstruction, is primary: a fixed-seed 10% of evidence pairs is withheld before layout and scored by a **degree-matched** link-prediction AUC — the probability that a withheld pair's true partner sits closer than a random partner drawn in proportion to degree. Comparing against uniformly drawn random pairs is confounded: withheld edges over-sample hubs, and uniform repulsion packs hubs into a core, so on 2026-11-19 uniform repulsion scored 4.2–4.5× "closer than random" with real weights and 4.2–4.4× with shuffled weights — a score that ignores the weights' meaning. Held-out labels are secondary. Replica and GPU, spokes removed, three seeds with intervals, scored against the full evidence graph and held-out labels: (a) undamped weighted LinLog with matched strength at `δ ∈ {0, 0.5, 1}`; (b) the same with damping `α ∈ {0.25, 0.5}` as an ablation, also on a hub-heavy unequal-community synthetic graph to check whether damping weakens genuine bridges; (c) a shuffled-weight null for each; (d) constraints on/off. A default is adopted only where it beats its shuffled null outside the seed interval.

## Pre-registered: ontology mode (D5), recorded 2026-11-19 before any result

Live constraints are off (operator decision, 2026-11-19) pending this test. Cause found first: the live set is built from the reasoner's transitive closure — 10,958 direct `subClassOf` pairs become 55,181 closure pairs, and "Artificial Intelligence" gains 4,820 descendants (the node carrying 4,925 constraints).

- **Validity gate.** The replica implements the live DISTANCE constraint exactly (`visionclaw_unified.cu:694-763`, per-node cap `constraintMaxForcePerNode`, ramp, strength placement) and the live set (closure, partOf/has-part deduped, sibling alignment capped at 20,000, `same-as`), and must reproduce the live A/B's *relative* kNN loss (≈30%, domain lift flat) under uniform repulsion with spokes present. If it does not, no arm is reported; the next step is a dump of the real constraint buffer.
- **Arms:** A0 off; A1 live set; A2 asserted direct parents only, same kernel, no siblings; A3 no constraint kernel, hierarchy affinity raised in the evidence graph; A4 the better of A2/A3 with each parent link scaled by the parent's intrinsic information content (Sánchez et al. 2011), so broad classes pull weakly; A5 shuffled-parent null (child counts preserved) on the best of A2–A4. Strength is swept on the winner only. Disjointness is excluded (3 corpus pages declare it).
- **Holdout.** The existing fixed-seed 10% evidence holdout; the hierarchy and constraints are built from training pairs only.
- **Metrics.** Primary: hierarchy AUC — for withheld `subClassOf` pairs, the probability that the child sits closer to its true parent than to a random parent drawn in proportion to child count. Guard: non-hierarchy degree-matched AUC and domain lift with spokes removed. Display only, never evidence: parent–child distance and sibling cohesion.
- **Adoption (opt-in mode only).** Hierarchy AUC beats A0 and A5 outside the seed interval; guard metrics within A0's seed interval; kNN lift loss ≤ 15% against A0. At least 3 seeds (5 where a comparison is close), Holm-corrected across arms × metrics, compared in StatCraft.
- **Gate result and amendment (2026-11-19, recorded before any arm was run).** The first gate failed: from a random start the replica settles at about 1/14 of the live scale (median pair distance 39 against 557), so the absolute rest length of 90 pushes closure pairs apart (100% of pairs inside the rest length, against 12% live). The live drop was −30% kNN with domain flat; the replica gave −50% kNN and −24% domain. Also established: sibling alignment is inert live (`alignment_strength` is 0.0), and partOf is not closed (12,205 pairs). Amended protocol: (1) the gate is re-run as the live A/B was, warm-started from the settled live positions (the `graph3.json` snapshot), with raw per-edge weights on the multi-edge graph, uniform repulsion and spokes present, toggling constraints on that layout; (2) if the gate passes, every arm uses the same warm start; the holdout pairs are removed before the warm-start layout is relaxed, for 1,500 steps, and only then is the arm applied; (3) no other metric or rule changes. If the amended gate fails, the replica is not used for D5, and the decision falls back to the live A/B plus a dump of the real constraint buffer. Design note, independent of the outcome: constraints with absolute rest lengths are not scale-invariant, because their effect depends on the force balance. A scale-free form (hierarchy as attraction affinity, arm A3) is preferred unless it measures worse.
- **Amended gate result (2026-11-19): fail clause applied.** Warm-started from the live layout (median pair distance 557), the replica collapses to 36 within 1,500 steps under the live balance and uniform repulsion, the repulsion mode in force when the snapshot was taken. The headline numbers sat inside the windows (kNN −38%, domain −9%), but they were measured on a layout 15× too compact, where rest length 90 acts as repulsion. Cause: the live step also runs the semantic kernels (`semantic_forces.cu`: collision, type cluster and the others), which the replica does not model and which hold the live scale. Replica comparisons between arms (weighting, repulsion mode) are unaffected; absolute-unit constraints cannot be judged in it. Per the amendment, the replica is not used for D5. Live constraints stay off. A replacement ontology mode is tested on the live kernel behind a stored opt-in setting, with its own pre-registration.
- **Live protocol for the scale-free ontology mode (recorded 2026-11-19, before any run).**
  - **Mode.** In the single weighting function, each asserted direct `subClassOf` edge (provenance `asserted`; inferred copies are excluded) gets weight × (1 + a·IC_norm(parent)), where IC is Sánchez intrinsic IC over the asserted hierarchy. `a` is the stored `hierarchyAffinity` (0 = off). There is no constraint kernel and no rest length. Weights are re-uploaded in place; positions are untouched.
  - **Holdout.** A fixed-seed (2204) 10% of asserted hierarchy edges are set to weight 0 and excluded from IC, in every arm including off, for the whole experiment (dev-only experiment control).
  - **Arms.** off (a = 0); a = 1; a = 2; null (a = 2 multipliers applied to the same number of random non-hierarchy edges).
  - **Schedule.** Three cycles of off → a1 → off → a2 → off → null. Each phase settles for 120 s, then takes three probes 30 s apart; the phase value is their median. Each arm is compared with the off phase immediately before it.
  - **Metrics.** Primary: hierarchy AUC on the withheld pairs, the probability that a child sits closer to its true parent than to a random parent drawn in proportion to child count. Guards: kNN lift scored on non-hierarchy edges only; domain lift. Spokes are present in every arm, so domain lift is a guard, not evidence. Display only: the parent–child distance ratio on non-withheld asserted pairs.
  - **Adoption** (as an opt-in mode). In all three cycles the arm's hierarchy AUC exceeds both its adjacent off phase and the null phase in the same cycle. Its mean gain over off exceeds the spread across the off phases. Non-hierarchy kNN lift falls by no more than 15% against the adjacent off phase. Domain lift stays within ±5%. Holm-corrected across the two arms; paired by cycle in StatCraft. Repeated phases on one evolving layout are not independent samples, so the tests are descriptive and the all-cycles rule is the decision.
  - **Confounds held fixed.** Uniform repulsion (no community detection anywhere during the run), ontology constraints off, one writer, and `hierarchyAffinity` and the experiment restored to off at the end.
  - **Fallback.** If no arm passes, the mode ships disabled as a legibility aid at most, or not at all, and the mapper's closure and sibling paths are deleted.
- **Live result (2026-11-19 14:47–15:50, build `e475f465e`; raw data in the session scratchpad, `onto-live-ab.csv`).** With the mode off, hierarchy AUC is already 0.942 (mean of the off phases; sd 0.0012, range 0.0039). The authored topology places children next to their withheld parents without any hierarchy force.
  - **a = 1:** above the adjacent off phase in all 3 cycles (+0.0018, +0.0018, +0.0017) and above the null in all 3 (+0.0006, +0.0018, +0.0011). Non-hierarchy kNN +0.7 to +3.9%; domain −0.4 to +0.1%; parent–child distance −5.2% (display only).
  - **a = 2:** fails the all-cycles rule (+0.0022, −0.0015, −0.0002 against off); parent–child distance −9.4%.
  - **Verdict under the rule as written:** a = 1 meets every clause except "mean gain exceeds the spread across the off phases". The gain of 0.0018 exceeds the off phases' standard deviation (0.0012) but not their range (0.0039). The rule did not say which spread was meant, so the conservative reading (range) is taken and the mode is **not adopted** as a prediction mode.
  - **Disposition:** under the fallback clause, the mode ships **disabled by default** (`hierarchyAffinity` 0) and may be used as a legibility aid: children land about 5% closer to their parents at no cost to fidelity or domain structure.
  - **Follow-up actions:** the constraint mapper's closure and sibling paths are deleted. The paired tests were computed in Python, not in StatCraft, because StatCraft reports to 2 decimal places and could not resolve effects of 0.002.
- **Outcomes.** A winner becomes a D5 rewrite and a stored mode setting. If A3 or A4 wins, the mapper's closure and sibling paths are deleted. If nothing beats A0, constraints stay off and D5 narrows to the ontology-tension lens (layout positions contradicting declared axioms, surfaced for curation) or removal.

## Pre-registered: extra-kernel A/B (S4c), recorded 2026-11-20 before any run

Context: after S4a (`6aeed03ce`), settled live kNN lift is 28 (uniform repulsion), against 44 on 19 Nov. The graph now carries 5,275 inferred `subClassOf` edges (provenance `inferred`) on top of 10,895 asserted ones. The replica, which has no semantic kernels, scores both graphs alike (54 against 56), so the drop is in a live-only term. The attribute-spring rest length `max − w·(max−min)` is negative for w > 1.18, and hierarchical edges weigh 1.6.

- **Arms** (each switched through the physics settings PUT `semantic.<kernel>.enabled`, everything else unchanged): K0 = current (attribute spring and cross-domain on); KA = attribute spring off; KX = cross-domain off; KB = both off. The dynamic-relationship kernel has no switch and is not tested here.
- **Schedule.** Three cycles of K0 → KA → K0 → KX → K0 → KB. Each phase settles 120 s, then takes three probes 30 s apart; the phase value is their median. Each arm is compared with the K0 phase immediately before it.
- **Metrics.** kNN lift (all non-spoke edges) and domain lift; guard: median pair distance.
- **Decision rule.** For each arm, compute the paired difference arm − preceding K0 per cycle.
  - **Retire** (when that arm's kernel set is off): in all three cycles, kNN lift and domain lift are both ≥ the preceding K0, the mean kNN gain exceeds the **standard deviation** of the nine K0 phases, and median pair distance stays within ±25% of K0.
  - **Keep** (load-bearing): in all three cycles, kNN lift or domain lift falls below the preceding K0 by more than that standard deviation.
  - **Otherwise:** inconclusive; the kernel stays and the result is reported.
- **Held fixed.** Uniform repulsion, constraints off, Legacy weighting, `hierarchyAffinity` 0, one writer; every kernel is restored to on at the end.
- **Result (2026-11-20 02:50–03:51, build `6aeed03ce`).** K0 baseline kNN lift 28.71 (sd 0.296 over nine phases), domain lift sd 0.024.
  - **KA (attribute spring off): KEEP.** kNN −1.84 / −2.16 / −1.20, domain −0.19 / −0.13 / −0.12 against the preceding K0 phase; median pair distance +22 to +24%.
  - **KX (cross-domain off): inconclusive.** kNN +0.02 / −0.19 / +0.10, domain within ±0.013, scale ±1%. The kernel has no measurable effect.
  - **KB (both off): KEEP,** the same as KA.
  - **Reading.** The attribute spring is load-bearing: it holds the layout about 20% tighter and raises fidelity. Its negative rest length (w > 1.18) therefore acts as useful extra attraction on strong edges, not as a defect to delete. D4's "one attraction term" must absorb it as a measured change (for example the attraction exponent δ, or a weight transform), not a silent removal. The cross-domain kernel is neutral and is a removal candidate once D4's replacement lands.
  - **The 44 → 28 drop is not explained by these kernels:** removing them lowers lift further. The inferred-`subClassOf` follow-on below is the remaining candidate.
- **Follow-on, not part of this decision:** inferred `subClassOf` edges in the physics graph (D2 says hierarchy contributes direct asserted parents only). They are tested separately by turning off `materialiseInferredEdges` and resyncing.

## Pre-registered: inferred-hierarchy-edge A/B, recorded 2026-11-20 before any run

Context: the live graph carries 5,275 `hierarchical` edges with provenance `inferred` (immediate inferred parents from the reasoner, capped per child, ADR-2071; not the full closure) beside 10,895 asserted ones. `qualityGates.materialiseInferredEdges = false` purges stored inferred edges on the next sync (`github_sync_service.rs` `purge_inferred_edges`), and `true` re-creates them, so the arm switch is the setting plus an incremental sync.

- **Arms.** I1 = inferred edges on (current); I0 = off. Schedule: I1 → I0 → I1 → I0 → I1. Each I0 phase is compared with the I1 phases on either side (their mean).
- **Per-phase procedure.** Set the gate, trigger `POST /api/admin/sync`, then confirm the count of `provenance: inferred` edges in REST (0 for I0; above 5,000 for I1). After the re-upload, wait until the mean frame displacement stays below 0.1 for two consecutive probes (record the time taken, cap 20 min). Then take three probes 30 s apart; the phase value is their median.
- **Frozen scoring set.** kNN lift and domain lift are scored in every phase against one edge set frozen before the run (asserted, non-spoke, non-inferred edges from the 2026-11-20 snapshot), so a changing neighbour set cannot move the metric. Guard: median pair distance.
- **Decision rule.** Effect = mean over the two I0 phases of (I0 − mean of adjacent I1). The standard deviation is that of the three I1 phases. **Inferred edges harm the layout** if both I0 phases exceed their adjacent I1 mean on kNN lift, and the mean effect exceeds 2 × that SD. **They help** under the mirror condition. Otherwise neutral.
- **If they harm:** the end state is D2/D7. Inferred hierarchy edges stay in the store and on the wire with their provenance, but contribute nothing to physics in every weighting mode. Leaving the gate off is not the fix, because it also removes them from view.
- **If neutral:** the remaining graph changes since 19 Nov are tested next: S3's co-citation fan-out boundary, and `explicit_link` labels reaching the registry and the dynamic-relationship kernel, which S4b gives an `enabled` switch whatever the result.
- **Held fixed.** Uniform repulsion, constraints off, Legacy weighting, `hierarchyAffinity` 0, both semantic kernels on, no community detection, one writer. The gate is restored to on at the end.
