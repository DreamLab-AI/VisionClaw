# Menu audit — desktop and XR, 2026-11-06

Scope: every menu, panel, chip and hotkey on the desktop client, and every HUD and menu surface in the Godot XR client. Audited at `c360202db` (branch `feat/gv-menus`). The desktop part used the code and the live dev app at `http://visionclaw_container:3001/` (1280x900 and 1024x768). The XR part used the code only, because no headset was available. The proposed information architecture is in [ADR-2189](../adr/ADR-2189-desktop-and-xr-menus-share-one-seven-section-information-architecture.md).

**My inputs.** I did not change any settings myself. My only inputs were these:
- one click on the "Look & Materials" icon;
- one Escape keypress;
- resizing the window to 1024x768 and back to 1280x900.

**A setting changed while I worked, cause unknown.**
- At the start, the Memory explorer panel was open and the memory cloud was drawn. That panel is only shown while `embeddingCloud.enabled` is on.
- By the time the control centre was open, the panel and the cloud were gone. At the end, `localStorage` held `visualisation.embeddingCloud.enabled: false`.
- I don't know the cause. It could be another lane sharing the browser, or a server push. The Look values I read at the start were unchanged at the end: `colorScheme` sssp, `sizeScheme` fileSize, `nodeSize` 0.25, node `#c25b5b`, edge `#a30000`, width 0.04, opacity 0.30.
- I did not restore the setting, so that I would not overwrite another lane's change.

## 1. Method

- **Dead-control scan.** For each of the 257 path-bearing entries in `client/src/features/control-center/registry/settings-manifest.json` (268 entries, 11 of them pathless actions), the script searched `client/src` for readers.
  - Excluded: the registry and manifest themselves, defaults (`api/settings/defaults.ts`), type declarations (`features/settings/config/settings.ts`, `api/settings/types.ts`, `store/settings/settingsTypes.ts`), tests, and the writers `CommandInput.tsx`, `MacroBar` and `macros.ts`.
  - A hit is either the full dotted path, or the leaf key as a property access in a file that also names the parent key.
  - Server-bucket physics paths were also checked in Rust, in `src/` and `crates/`.
  - Every path with no reader was then confirmed by hand with `grep -rln "\b<leaf>\b" client/src` (results in §4).
  - The leaf heuristic over-counts readers when leaf names are generic (`opacity`, `enabled`, `color`). So the `visualisation.graphs.visionclaw.*` and `xr.*` paths were traced by hand, and that check is what put them on the dead list.
  - The script is reproduced in Appendix B. To re-run it: `node dead.js <worktree> readers.json`.
- **Live probes.** `elementsFromPoint` at control centres, bounding rectangles from `getBoundingClientRect`, and the accessibility tree.
- **Code inventories** of the dock, chips, palette, CommandInput, persistence and hotkeys (desktop), and of `hud.gd`, `radial_menu.gd`, `query_builder.gd`, `dwell_reticle.gd`, `graph_scene.gd` and `xr_prefs.gd` (XR).
