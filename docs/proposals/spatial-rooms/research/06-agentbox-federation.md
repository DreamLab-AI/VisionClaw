Paths: AB = <VC>/agentbox, VC = <VC repo root>, SPR = <solid-pod-rs repo root>.
Tags: [V] verified at path:line this session; [D] from docs/memory, not verified against running code.
Honest headline (agentbox + VisionClaw only; the forum has a shipped mesh crate, see §1): "federation" today is **one VisionClaw↔one agentbox identifier/kind contract + a live agent-action WebSocket**. Node-to-node federation (peer relays, remote pods, foreign agentbox) is **declared in manifest/docs but has no code consumer**.

Peer definition today: a **peer** = a did:nostr pubkey on the baked allowlist (relay/inbox) or a followed `<pubkey>/<repo>` (forge mirror) or a container on the shared docker bridge `visionclaw_network` (`docker-compose.yml:214`; `PROTOCOL-registry.md:34-35` warns any peer container on that bridge can reach the loopback-published ports) [V]. There is no peer registry, no handshake, no discovery.

### The one live agentbox→VC runtime path (not relay-based)
`/wss/agent-events` WebSocket, `notifications/agent_action` carrying `source_urn/target_urn/pubkey` (`docs/developer/ecosystem.md:206-215` sequence diagram) [V]. Reverse "bi-directional graph-state ingress" via IS-Envelope `knowledge_link` over relay→pod-inbox bridge is drawn in the same diagram (:217-220) but VC code for it not found (see §4) [D].

## 3. Data-space primitives
- "Data space" is not a defined term. Candidates and their handles [V unless noted]:
  - **Solid pod**: URN kind `pod` (owner-scoped, content-addressed, surface `pods`) `AB/management-api/lib/uris.js:89`; also envelope/credential/mandate/receipt on surface `pods` (:90-93). Served by solid-pod-rs on :8484 (`identity-mesh.md:360`).
  - **Dataset**: URN kind `dataset` (owner-scoped, scope required, NOT content-addressed, surface `memory`) `uris.js:106`. Resolver `memory` branch redirects to `/v1/memory/<key>?namespace=<ns>` (`AB/management-api/routes/uri-resolver.js:116-126`). It is a RuVector memory namespace, not a graph.
  - **Knowledge** kind (ADR-2085, additive, content-addressed with scope) per ADR-2025 re-verification 2026-09-21 [V].
  - **Thing** (`uris.js:101`) is the only data-bearing kind that crosses to VC (→ `urn:visionclaw:kg:<pk>:<sha12>`).
  - **Ontology corpus**: `[vault]` single corpus authority (AGENTS.md); no URN kind, accessed by the `vault` CLI / Loom, not federated [V AB/AGENTS.md].
  - **Forum zone**: nostr-rust-forum kits; not examined in depth here [not verified].
- Not federated (refused `unmapped-kind`): pod, dataset, memory, envelope, credential, receipt… i.e. **every pod/dataset URN is refused at the VC boundary today** (`schema/federation-kinds.json`, ADR-2061 :154-156) [V].
- `/v1/uri/:urn` resolver (`uri-resolver.js:49`): returns 307 to a **local** surface (`/v1/memory/...`, pods, beads) or 404; 410 documented but never emitted (header :18-22). did:nostr → local `/.well-known/did.json` only if `[linked_data].did_documents` enabled (:62-70). It never redirects to another node's host except by repointing adapters in `federation.mode=client` (`identity-mesh.md:360`). `GET /v1/uri` lists kinds with `surface` (:167-175). Linked-object viewer `/lo/*` (`routes/linked-objects.js:1-20`) follows one redirect of `/v1/uri/<urn>` against `policy.apiBase` (:90,228) — a seam for remote-node dereference.
- Pod mirror replicates **git repositories only** (kind-30617 announce / 30618 state, not pod RDF): follow list of `<pubkey>/<repo>`, relays named, `git fetch` per state change, verified by sig + blocktrails marks (`SPR/crates/solid-pod-rs-forge/src/mirror.rs:1-25`; server env `FORGE_MIRROR_FOLLOW` at `SPR/crates/solid-pod-rs-server/src/lib.rs:4961-4968`) [V]. No LDN involved in mirror. LDN is the **inbox** path: relay event → `nostr-pod-bridge` admission → durable LDN doc in pod inbox (`admission.rs:27`) [V]. There is no Solid-resource (RDF/ACL container) replication between pods.

## 6. Identity and keys
- VC today signs relay/bridge events with **env hex key** `VISIONCLAW_NOSTR_PRIVKEY` (`nostr_bridge.rs:37`, `nostr_bead_publisher.rs:40`, ACSP panel fallback chain `services/acsp/key_file.rs:16,43`; compose passes it `docker-compose.unified.yml:151,290`) [V]. `SERVER_NOSTR_PRIVKEY` is a second identity (archive Q2/Q4 audits) [D]; PRD-010 F1 meant to unify them (DDD :128) [D, status unknown]. VC NIP-98 caller identity per `VC/docs/IDENTITY-authority-chain.md:32-40`; service-signed ≠ delegation (:196-202).
- Agentbox identity port (`/run/secrets/ab-identity-port/identity.sock`, `nostr-pod-bridge sign-request <op>`) is **agentbox's** sovereign key `core` (`AGENTBOX_PRIVKEY_HEX`) and `junkiejarvis`; closed op list, kinds 31400-31405/38414/27235/22242 not grantable (ADR-2122:294-296). It is callable only by uids in its ACL (devuser, ab-gateway); VC backend runs in a different container and has no ACL entry. Off by default (role_isolation flag) [V].
- Recommendation for the lead (analysis, not fact): a VC node should NOT reuse agentbox `core` nor `k_id`. ADR-2101:59-74 says federation signer keys are domain-separated from identity and never in `identity.env`; the port's ACL would need a new `visionclaw-federation` caller+key and new kind numbers outside the forbidden set. Smallest compatible path: dedicated VC key via `VISIONCLAW_NOSTR_PRIVKEY` (or `*_KEY_FILE` per `key_file.rs`) as interim; migrate to an identity-port-style custody later. Peer pubkeys must be admitted via `allowed_remote_dids`-equivalent (today rebuild-class per ADR-2012).
